# A Hallucination is a NavMesh shell with a sanitized visual clone, never a PlayerAvatar copy

A Hallucination is built from the `MyDroid` prefab (NavMeshAgent + CharacterController, every Photon and enemy script stripped) onto which a live clone of the Imitated Player's visuals is grafted, keeping only renderers, animator, cosmetics and player materials. Copying the game's `PlayerAvatar` instead does not work: its `Awake` destroys the copy because it shares the real player's PhotonView owner, and if it survived it would join `GameDirector.PlayerList` (so enemies would target it), its `OnDestroy` would tell every enemy the real player left and destroy the whole player root, and it would drag along networked and input-driven parts (grabber, health, voice chat, flashlight, map tool) that ADR-0002 keeps off the network.

The clone's body is animated by the game's own `PlayerAvatarVisuals`, on its remote-player path. That is what gives a teammate seen by others its body spring, lean, sprint tilt, head turning and leg twist (#65). Its `playerAvatar` must be a real `PlayerAvatar` component, so it is pointed at a fake one held on a GameObject that is deactivated before any component is added and never activated. Unity then never runs the fake's `Awake`, `Start`, `Update` or `OnDestroy`, which is the pattern of the game's own `PlayerAvatar Dummy.prefab`, whose `Player Avatar Controller` is inactive. The Hallucination writes the fake's position, rotation, velocity and movement flags each frame. A Harmony prefix stops the fake's animation-event callbacks (`Footstep` and the crouch transitions), since a footstep on the Master makes enemies investigate.

## Considered Options

- **Menu-avatar mode** (`PlayerAvatarMenu` / `isMenuAvatar`): rejected after reading `PlayerAvatarVisuals`. Menu mode skips the whole locomotion block: there is no body spring, no velocity lean, no sprint tilt, no turn-driven head steer and no velocity leg twist, and the game never makes a menu avatar walk. It also binds the local player, here the Victim, so the head would pitch with the Victim's crouch, and it re-applies the Victim's cosmetics.
- **Rewriting the body animation on the clone's rig**: workable through the game's public spring helpers (`SemiFunc.SpringQuaternionGet`), but it copies about 270 lines of `PlayerAvatarVisuals` that would drift from the game's updates. It was dropped once the prototype showed the never-activated fake works.
- **The fake's limits**: `PlayerAvatarVisuals` takes the local path in singleplayer and hides the body. There is no Hallucination in singleplayer outside the dev tools, so this only affects testing.
